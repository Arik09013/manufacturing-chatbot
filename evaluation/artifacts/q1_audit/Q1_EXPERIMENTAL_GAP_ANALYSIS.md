### Experiment 1: Benchmark Validation on Real Physical Welding Sensor Data

* **Research Question:**  
  Does the proposed multimodal defect detection pipeline maintain high diagnostic accuracy and attribution stability when transferred from synthetic data to real-world industrial arc welding sensor streams?
* **Hypothesis:**  
  Real physical arc welding data contains high electromagnetic interference (EMI), torch vibration, and transient spatter noise; while simple linear models will degrade significantly, tree ensembles with domain-engineered rolling features will achieve viable defect detection ($F_1 > 0.80$), though well below the synthetic ceiling of 1.0000.
* **Dataset Required:**  
  Open-access physical arc welding benchmark (e.g., the *Intel Robotic Welding Multimodal Dataset* containing $>4,000$ annotated samples of video, audio, and electrical parameters, or public GMAW weld monitoring datasets from NIST / RW-Welding repositories).
* **Methodology:**  
  1. Map real weld sensor channels (welding current, arc voltage, wire feed rate, shielding gas flow, acoustic emissions) into the existing windowing and feature extraction pipeline.
  2. Implement chronological training/testing splits with temporal embargoes matching factory production runs.
  3. Evaluate detection performance on real physical defect categories (e.g., burn-through, lack of penetration, porosity, tungsten inclusion).
* **Metrics:**  
  Precision, Recall, Macro $F_1$, PR-AUC, ROC-AUC, False Positive Rate (FPR), and Cohen's Kappa under chronological holdout.
* **Expected Reviewer Concern Addressed:**  
  Directly eliminates **Attack Vector 1** (synthetic-only trivial separability) and validates external real-world generalizability.

### Experiment 2: Physical / Metallurgical Weld Quality Validation of Parameter Recommendations

* **Research Question:**  
  Do the parameter recommendations generated by the physics-based advisor produce defect-free weld joints meeting standard structural quality criteria (AWS D1.1 / ISO 5817 Level B)?
* **Hypothesis:**  
  Workpieces welded using the optimized parameter set (current, voltage, travel speed) will exhibit acceptable penetration depth-to-width ratios ($D/W \in [0.8, 1.5]$), absence of burn-through or lack of fusion, and superior tensile strength compared to unoptimized or boundary parameters.
* **Dataset Required:**  
  Physical weld test specimens (e.g., 5 mm and 8 mm mild steel and stainless steel butt joints) welded under: (a) baseline handbook midpoint settings, (b) proposed optimizer recommended settings, and (c) intentional edge/out-of-window settings.
* **Methodology:**  
  1. Perform physical GMAW/MIG weld passes on standardized test coupons.
  2. Section weldments, polish, and etch with Nital solution for optical metallographic macrography.
  3. Measure physical bead geometry: penetration depth, bead width, reinforcement height, and heat-affected zone (HAZ) width.
  4. Perform transverse weld tensile tests to confirm joint breaking strength meets base metal tensile requirements.
* **Metrics:**  
  Penetration depth (mm), bead width (mm), dilution percentage (%), tensile yield and ultimate tensile strength (MPa), failure location (base metal vs weld metal), and compliance with AWS D1.1 visual acceptance criteria.
* **Expected Reviewer Concern Addressed:**  
  Directly eliminates **Attack Vector 2** (complete absence of metallurgical ground truth) and transforms theoretical handbook calculations into empirically validated manufacturing science.

### Experiment 3: Benchmarking Against Modern Deep Learning & Gradient Boosted Time-Series Baselines

* **Research Question:**  
  Does the proposed Random Forest and DistilBERT feature pipeline provide measurable performance, efficiency, or interpretability advantages over modern deep learning and gradient boosted time-series models?
* **Hypothesis:**  
  Gradient boosted trees (XGBoost, LightGBM) will match Random Forest accuracy with lower memory footprint, while 1D-CNN and Temporal Convolutional Networks (TCN) trained directly on raw time-series will capture high-frequency transients missed by 30-minute summary aggregations.
* **Dataset Required:**  
  Both the existing 1,917-window benchmark and the physical welding dataset identified in Experiment 1.
* **Methodology:**  
  1. Implement modern tabular baselines: **XGBoost**, **LightGBM**, and **CatBoost**.
  2. Implement native time-series deep learning baselines: **1D-CNN**, **Bi-LSTM**, **Temporal Convolutional Network (TCN)**, and **PatchTST** (time-series transformer) trained on raw 1-minute (or sub-second) sensor arrays.
  3. Compare against the existing Random Forest and text-serialized DistilBERT under identical chronological holdout and LOMO cross-validation splits.
* **Metrics:**  
  Macro $F_1$, PR-AUC, training time (s), inference latency per window (ms), memory footprint (MB), and parameter count.
* **Expected Reviewer Concern Addressed:**  
  Directly eliminates **Attack Vector 9** (missing competitive state-of-the-art baselines) and establishes whether deep learning or manual feature aggregation is scientifically justified.

### Experiment 4: Scaled Industrial RAG Benchmark on Uncurated Engineering Standards

* **Research Question:**  
  How does the hybrid retrieval architecture scale when deployed across large-scale, uncurated industrial welding codes containing conflicting terminology, tables, and complex technical clauses?
* **Hypothesis:**  
  Full hybrid retrieval (BM25 + Dense) will significantly outperform pure dense and pure lexical search on technical welding codes (where specific alphanumeric codes like "ER70S-6", "E71T-1", "ISO 15614-1" require lexical precision, while conceptual defect queries require semantic retrieval).
* **Dataset Required:**  
  Full, uncurated digital PDF specifications of major welding standards (e.g., AWS D1.1 Structural Welding Code, ASME Boiler and Pressure Vessel Code Section IX, ISO 5817, and OEM equipment maintenance manuals) totaling $>1,000$ pages ($>5,000$ chunks), alongside an independent evaluation suite of 250 queries curated with certified welding inspectors.
* **Methodology:**  
  1. Ingest multi-document PDF standards using semantic and hierarchical chunking.
  2. Evaluate retrieval performance across varied chunking strategies (fixed 500-token, semantic header-based, and sliding-window).
  3. Benchmark lexical (BM25), dense (`all-MiniLM-L6-v2`, `bge-large-en-v1.5`), and hybrid reciprocal rank fusion (RRF) at $K \in \{1, 3, 5, 10, 20\}$.
  4. Perform paired permutation tests and persist per-query reciprocal rank matrices.
* **Metrics:**  
  Recall@K, Precision@K, Mean Reciprocal Rank (MRR), Normalized Discounted Cumulative Gain (NDCG@K), latency (ms), and index memory size.
* **Expected Reviewer Concern Addressed:**  
  Directly eliminates **Attack Vector 5** (benchmark circularity and toy-scale evaluation in RAG).

### Experiment 5: Genuine Physics-Regularized Machine Learning Loss Formulation

* **Research Question:**  
  Does incorporating physical arc thermodynamics and heat dissipation constraints directly into the loss function improve anomaly detection sample efficiency and out-of-distribution cross-station generalization?
* **Hypothesis:**  
  A neural network trained with a physics-informed loss term ($\mathcal{L} = \mathcal{L}_{\text{BCE}} + \lambda \mathcal{L}_{\text{thermal}}$), penalizing predictions that violate empirical cooling rate boundaries ($t_{8/5}$ limits) and energy conservation, will outperform unconstrained models when trained on low-sample regimes (e.g., only 10% labeled anomalies).
* **Dataset Required:**  
  Current master dataset (`fused.parquet`) and physical welding data partitioned into low-resource training splits (5%, 10%, 20% labeled anomaly fractions).
* **Methodology:**  
  1. Formulate a differentiable thermal loss function $\mathcal{L}_{\text{physics}}$ based on the Rosenthal 2D/3D moving heat source solution and carbon-equivalent cooling times ($t_{8/5}$).
  2. Train a multi-layer perceptron (MLP) or 1D-CNN with loss $\mathcal{L}_{\text{total}} = \mathcal{L}_{\text{data}} + \lambda \mathcal{L}_{\text{physics}}$.
  3. Evaluate out-of-distribution generalization across held-out stations and low-data regimes against standard unconstrained ML models.
* **Metrics:**  
  Few-shot $F_1$ curve vs training sample size, constraint violation rate (%), cross-station LOMO degradation ($\Delta F_1$).
* **Expected Reviewer Concern Addressed:**  
  Directly eliminates **Attack Vector 3** (mischaracterization of "physics-informed AI") and provides a legitimate, publishable methodological contribution in physics-guided industrial machine learning.

### Experiment 6: Cross-Modal Cross-Attention Architecture for Heterogeneous Factory Data

* **Research Question:**  
  Can a dedicated cross-attention transformer architecture learn synergistic, non-redundant cross-modal representations between continuous sensor streams, discrete PLC event logs, and unstructured operator notes?
* **Hypothesis:**  
  A cross-attention fusion network—where query tokens from unstructured shift notes attend to time-aligned sensor patch tokens and discrete event embeddings—will achieve statistically significant performance gains over tabular concatenation when sensor data is partially noisy or occluded.
* **Dataset Required:**  
  Multimodal welding dataset with injected sensor dropouts, missing channels, and authentic operator log notes.
* **Methodology:**  
  1. Implement a multimodal transformer architecture (e.g., Cross-Modal Attention Transformer, CMAT):
     - Sensor branch: 1D temporal patch projection.
     - Log branch: Learned event-code embeddings.
     - Note branch: DistilBERT token embeddings.
     - Fusion: Multi-head cross-attention layer linking text queries to sensor keys/values.
  2. Perform systematic modality masking (sensor dropout 10% to 50%) to test whether the cross-attention mechanism dynamically re-weights text notes to compensate for missing sensor channels.
* **Metrics:**  
  Macro $F_1$, cross-modal attention map interpretability, deletion AUC under sensor degradation, and paired Wilcoxon test against early tabular concatenation.
* **Expected Reviewer Concern Addressed:**  
  Directly eliminates **Attack Vector 4** (empirical redundancy of operator notes) and **Attack Vector 11** (incompatible feature spaces in XAI), fulfilling the original thesis vision of true cross-attention multimodal fusion.

### Experiment 7: Semantic Intent Classifier Benchmarked Against Realistic Shop-Floor Noise

* **Research Question:**  
  Does a learned semantic intent classifier (e.g., SetFit or fine-tuned compact transformer) provide superior robustness and generalization over hardcoded regex keyword matching on diverse, uncurated operator prompts?
* **Hypothesis:**  
  A lightweight learned sentence transformer classifier (SetFit / MiniLM) will maintain $>95\%$ intent classification accuracy on colloquial, misspelled, and code-switched shop-floor operator queries, whereas keyword regex systems will degrade below 75% on uncurated queries.
* **Dataset Required:**  
  An expanded intent benchmark of 500+ diverse queries collected from welding technicians, shop-floor apprentices, and non-native English operators, including colloquial jargon, spelling errors, and syntactic ambiguities.
* **Methodology:**  
  1. Train and evaluate a SetFit (few-shot sentence transformer) and fine-tuned MiniLM intent classifier across 5 target intents.
  2. Compare directly against the current regex/keyword router across 9 perturbation categories (typos, slang, negation, multi-intent).
* **Metrics:**  
  Macro $F_1$, Per-class Precision/Recall, Scope Guard False Rejection Rate (FRR), Inference Latency (ms), and model size (MB).
* **Expected Reviewer Concern Addressed:**  
  Directly eliminates **Attack Vector 10** (regex keyword matching presented as machine learning research).

### Experiment 8: Human-in-the-Loop Operator Usability & Decision-Time Study

* **Research Question:**  
  Does providing conversational XAI diagnostic explanations and physics-grounded parameter advice measurably reduce operator troubleshooting time and parameter setup errors?
* **Hypothesis:**  
  Welders and maintenance technicians utilizing the multimodal chatbot will resolve simulated station faults 40% faster and with 50% fewer parameter adjustment errors compared to operators relying solely on traditional paper manuals and raw alarm codes.
* **Dataset Required:**  
  Human subject cohort study ($N=15$ to $25$ welding apprentices and technicians) executing 5 standardized shop-floor troubleshooting scenarios.
* **Methodology:**  
  1. Divide participants into: (Group A) Control group with standard manuals and SCADA alarms, and (Group B) Experimental group with the Streamlit chatbot assistant.
  2. Record task completion time (minutes), root-cause diagnostic accuracy (%), and post-task System Usability Scale (SUS) scores.
  3. Measure subjective cognitive workload using the NASA-TLX index.
* **Metrics:**  
  Mean Time to Diagnosis (MTTD), Diagnostic Accuracy (%), SUS Score (0–100), NASA-TLX score, and Likert-scale perceived trust in SHAP/LIME explanations.
* **Expected Reviewer Concern Addressed:**  
  Directly addresses **Attack Vector 13** (lack of user-study validation), making the manuscript exceptionally attractive for human-centered manufacturing venues (*JMS*, *Computers in Industry*).

### Experiment 9: Real-Time Streaming Architecture & Sub-100 ms Inference Optimization

* **Research Question:**  
  Can the 3.3-second anomaly diagnosis bottleneck be reduced to sub-100 ms streaming latency through ring-buffer feature extraction and pre-computed TreeSHAP attributions?
* **Hypothesis:**  
  Replacing full pandas parquet slicing with a Cython/C++ circular ring-buffer and eliminating on-demand LIME sampling in favor of FastTreeSHAP will reduce end-to-end anomaly diagnostic latency from ~3,300 ms to $<50$ ms, enabling near-real-time automated weld cycle intervention.
* **Dataset Required:**  
  Simulated real-time streaming sensor feeds at 10 Hz and 50 Hz.
* **Methodology:**  
  1. Implement an incremental rolling feature extractor (updating running mean, variance, min, max in $O(1)$ time per sample).
  2. Replace LIME with optimized C-level TreeSHAP with path pruning.
  3. Benchmark latency and memory under continuous streaming load.
* **Metrics:**  
  P50, P95, P99 Latency (ms), CPU/Memory utilization, and maximum sustainable streaming ingestion frequency (Hz).
* **Expected Reviewer Concern Addressed:**  
  Directly addresses **Attack Vector 12** (3.3 s latency bottleneck), substantiating claims of real-time industrial readiness.

### Experiment 10: Non-Stationary Workpiece & Fit-Up Gap Sensitivity Sweep

* **Research Question:**  
  How sensitive are the physics-based parameter recommendations and defect classifications to non-stationary shop-floor disturbances, such as varying joint root openings (fit-up gaps) and surface contaminants?
* **Hypothesis:**  
  Static parameter recommendations will fail when root openings exceed $1.5$ mm without adaptive travel speed and wire feed adjustments; an adaptive tolerance boundary will prevent lack of penetration and burn-through across variable fit-up tolerances.
* **Dataset Required:**  
  Simulated or experimental welding trials with variable root openings ($0.5$ mm to $2.5$ mm) and surface mill scale/rust.
* **Methodology:**  
  1. Model root opening variation as a dynamic joint cross-sectional area multiplier.
  2. Perform sensitivity analysis of recommended current, voltage, and travel speed vs root opening width.
  3. Formulate an adaptive tolerance envelope in the parameter advisor.
* **Metrics:**  
  Parameter sensitivity gradient ($\frac{\partial \text{WFR}}{\partial \text{gap}}$), burn-through avoidance rate (%), and constraint satisfaction across non-standard joints.
* **Expected Reviewer Concern Addressed:**  
  Directly addresses **Attack Vector 14** (static joint geometry assumption).
